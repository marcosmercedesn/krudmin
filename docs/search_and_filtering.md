# Search and Filtering

Krudmin provides a powerful search system built on top of Ransack. Search filters are automatically generated from the `SEARCHABLE_ATTRIBUTES` in your Resource Manager, and filter state persists across page navigation via cookies.

## Overview

The search system consists of:

1. **SearchForm** (`lib/krudmin/search_form.rb`) — Builds the search UI and generates Ransack-compatible params
2. **Searchable concern** (`app/controllers/concerns/krudmin/searchable.rb`) — Manages search state and cookie persistence
3. **SearchFilter** (`lib/krudmin/search_form/search_filter.rb`) — Generates per-field filter descriptions
4. **CalendarFilter** (`lib/krudmin/search_form/calendar_filter.rb`) — Date/datetime range filtering
5. **SearchPhrasesSupport** (`lib/krudmin/search_form/search_phrases_support.rb`) — Maps operators to Ransack predicates
6. **SearchInputTypeSupport** (`lib/krudmin/search_form/search_input_type_support.rb`) — Determines input type per field

## Configuring Searchable Fields

In your Resource Manager, define `SEARCHABLE_ATTRIBUTES`:

```ruby
class ProductsResourceManager < Krudmin::ResourceManagers::Base
  SEARCHABLE_ATTRIBUTES = [:name, :price, :active, :category_id, :created_at]
  # ...
end
```

Each field type determines what search input and operators are available:

| Field Type | Search Input | Operators |
|------------|-------------|-----------|
| String/Text | Text input + operator dropdown | contains, equals, matches, less_than, greater_than, starts_with, ends_with |
| Number | Number input + operator dropdown | equals, less_than, greater_than, less_than_or_equal, greater_than_or_equal |
| Boolean | Yes/No dropdown | equals |
| Date/DateTime | From/To date pickers | Range (from/to) |
| BelongsTo | Select dropdown | equals |
| EnumType | Enum select dropdown | equals |

## Search Operators

Operators are mapped to Ransack predicates via `SearchPhrasesSupport`:

| Operator | Ransack Predicate | I18n Key |
|----------|-------------------|----------|
| contains | `:cont` | `krudmin.search.contains` |
| equals | `:eq` | `krudmin.search.equals` |
| matches | `:matches` | `krudmin.search.matches` |
| less_than | `:lt` | `krudmin.search.less_than` |
| greater_than | `:gt` | `krudmin.search.greater_than` |
| less_than_or_equal | `:lteq` | `krudmin.search.less_than_or_equal` |
| greater_than_or_equal | `:gteq` | `krudmin.search.greater_than_or_equal` |
| starts_with | `:start` | `krudmin.search.starts_with` |
| ends_with | `:end` | `krudmin.search.ends_with` |

## Search State Persistence

Search filters are persisted in cookies via `PersistedSearchResults` (defined in the `Searchable` concern). This means:

- Filters survive page navigation and pagination
- Each controller has its own cached search state
- Cached under the `krudmin_search_results` cookie key

### Resetting Search

Add `?reset_search=1` to any URL to clear the persisted search state for that resource.

In the UI, the search form includes a Reset button that triggers this.

## How Search Works Internally

### 1. User enters search criteria

The search form (`_search_form.html.haml`) renders inputs for each searchable field. Values are submitted as:

```
q[name]=camry
q[name_options]=cont
q[year]=2020
q[year_options]=eq
q[active]=true
```

### 2. Searchable concern processes params

The `Searchable` concern in the controller:
1. Merges old (`:o`) and new (`:q`) search params
2. Checks the cookie cache for persisted state
3. Respects `?reset_search=1` to clear
4. Builds a `Krudmin::SearchForm` with the merged params

### 3. SearchForm generates Ransack params

`SearchForm#params` converts human-readable criteria to Ransack format:

```ruby
# Input: { name: "camry", name_options: "cont", year: "2020", year_options: "eq" }
# Output: { name_cont: "camry", year_eq: 2020, s: "year asc" }
```

### 4. Ransack applies filters

The controller calls `item_list` which applies the Ransack search:

```ruby
scope.ransack(search_params).result
```

### 5. Results are paginated and rendered

Kaminari paginates the filtered results.

## Date Range Filtering

Date and DateTime fields automatically generate two search inputs: "From" and "To". These use special keys:

```
q[created_at__from]=01/01/2024
q[created_at__to]=12/31/2024
```

The `CalendarFilter` converts these to Ransack predicates:

```ruby
created_at_gteq: "2024-01-01"
created_at_lteq: "2024-12-31"
```

## Filter Descriptions

Active filters are displayed as human-readable strings above the results:

```
"name CONTAINS <camry>"
"year EQUALS <2020>"
"created_at FROM <01/01/2024> TO <12/31/2024>"
```

These are generated by `SearchFilter#filters` and `CalendarFilter`.

## Customizing Search

### Custom Sort Order

Define `ORDER_BY` in the Resource Manager for the default sort:

```ruby
ORDER_BY = [created_at: :desc]
```

Users can also sort by clicking column headers in the list view.

### Search by Association

To search by a belongs_to association, include the foreign key in `SEARCHABLE_ATTRIBUTES`:

```ruby
SEARCHABLE_ATTRIBUTES = [:name, :category_id]
```

This renders a dropdown populated from the associated model's records.

### Remote Search for BelongsTo

When a BelongsTo field has `remote: true` in `ATTRIBUTE_TYPES`, the search dropdown uses AJAX. The associated model should define a `search_by_term` scope:

```ruby
class Category < ApplicationRecord
  scope :search_by_term, ->(term) { where("name ILIKE ?", "%#{term}%") }
end
```
